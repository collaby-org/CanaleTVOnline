The upstream `canaletvlive.online` was reconstructed **without source code**, using only passive observation:

## Known gaps

1. **Token HMAC unknown — delegated to upstream mint.** The `?token={13digit-ms}-{64hex-sha256}` is generated by an unknown server-side HMAC. The clone does **not** implement token generation; it delegates minting to the upstream bulk endpoint and recovers via the `?_nc=` reload protocol (Section 9 of the admin guide). Consequence: playback quality depends on upstream freshness of the seed tokens.
2. **CSS is token-parity, not byte-identical Tailwind.** The upstream ships a single compiled 29,398 B Tailwind CSS file. The clone keeps it verbatim as `public/original.css` and hand-writes token-parity CSS for new components rather than reproducing the exact Tailwind utility set. Visuals match at the token level (colors, fonts, dark theme, spacing rhythm), but the generated class names and some responsive breakpoints (exact behavior beyond 767 px was never observable) differ.
3. **OG PNG generated locally.** `/api/og/watch/{slug}` (1200×630) is rendered locally (Satori-style) instead of proxying the upstream PNG (verified live 2026-11-04: 200 `image/png` 93,715 B for `protv`). Channel name/logo/branding are reflected, but the PNG is not byte-identical to upstream.
4. **Multistream uses `hls@latest`, watch uses pinned hls.js.** The watch page pins `https://cdn.jsdelivr.net/npm/hls.js@1.5.13/dist/hls.min.js` (upgraded from the chunk-observed version, with `MANIFEST_PARSED` quality list + `LEVEL_SWITCHED` chip). Multistream deliberately mirrors the upstream behavior of loading `hls.js@latest` (`lowLatencyMode:true`, native Safari path, single-audible mute policy). The two surfaces intentionally diverge.

## Corrections during this session

- **`/api/blog` numeric-404 correction:** early notes implied numeric blog ids might resolve (a later probe showed a 200-shaped response for one id). Verified 2026-11-04: `GET /api/blog/{numeric-id}` returns **404 `{error:'Not found'}`** (21 bytes); only **known slugs** return 200. The clone implements slug-only resolution.
- **`/api/channels` bulk-vs-naked distinction:** the bulk list (and SSR flight data) carries **tokenized** `stream_url` values refreshed on every request, while single-channel `GET /api/channels/{id|slug}` deliberately strips `?token=`. Conflating the two produced stale/dead playback. The clone preserves the distinction: bulk = playable, single = tokenless fallback.
- **Stream recovery protocol codified:** 403-specific reload vs. generic retry vs. `recoverMediaError` vs. native fallback were separated (documented in the admin guide, Section 9), replacing an earlier “reload on any fatal error” behavior that caused reload loops.

## Stream recovery protocol (summary)

Fatal `403 NETFORN_ERROR` → `?_nc=` reload once per session → other fatal `NETWORK_ERROR` → `hls.startLoad()` → media errors → `recoverMediaError()` → non-HLS browsers → native `<video>` fallback or error overlay.
